# KSerial 設定サンプル

[简体中文](README.md) · [English](README.en.md) · **日本語**

このディレクトリの `.conf` ファイルは、基本から高度な順に並んでいます。目的に近いサンプルをコピーし、ポート名、通信条件、ルールを変更してください。設定の読み込みでは検証と準備だけを行い、画面で「実行」を押した後にシリアルポートを開きます。

## `.conf` でコメントは使えますか？

使えます。KSerial は Typesafe Config を通じて [HOCON](https://github.com/lightbend/config#using-hocon-the-json-superset) を読み込みます。`#` と `//` のどちらも、行全体または行末のコメントとして使用できます。

```hocon
# 行全体のコメント
port = "COM2" // 行末のコメント
baudRate = 115200 # この形式も使用可能
```

実際の値に `#`、`//`、空白、エスケープシーケンスが含まれる場合は、コメントや複数のトークンとして解釈されないようにダブルクォートで囲んでください。設定の読み込みで使用できるのは HOCON の `.conf` / `.hocon` ファイルのみです。

## デバイス模擬のフィールド

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `simulator` | いいえ | 推奨されるルートオブジェクト。内部のフィールドをファイル直下に置くこともできます。 |
| `simulator.endpoint` | はい | この模擬で使用する完全なシリアル設定。ページに残った古い選択値は使用しません。 |
| `simulator.encode` | いいえ | `HEX` は 16 進バイトです。`ASCII`、`TEXT`、`UTF8`、`UTF-8` は UTF-8 テキストとして扱います。既定値は `UTF8` です。 |
| `simulator.delimiter` | どちらか一方のみ | 区切り文字によるフレーム分割。テキストモードでは通常の文字列、HEX モードでは HEX バイトを指定します。 |
| `simulator.packSize` | どちらか一方のみ | 1～4096 バイトの固定フレーム長。`delimiter` と同時には指定できません。 |
| `simulator.rules` | はい | 1 件以上の `request` / `response` ルール。`request` は重複しないようにしてください。 |
| `simulator.rules[].request` | はい | 1 フレームを受信した後に照合するリクエスト内容。 |
| `simulator.rules[].response` | はい | リクエスト一致時にシリアルポートへ書き込む応答内容。 |
| `simulator.rules[].delay` | いいえ | このルールの応答遅延。グローバルの `responseDelay` を上書きします。 |
| `simulator.responseDelay` | いいえ | グローバルの応答遅延。既定値は `0`（即時応答）です。 |
| `simulator.highlight` | いいえ | ログのキーワード、有効状態、大文字・小文字を区別するかどうかの設定。 |

`delimiter` と `packSize` は必ずどちらか一方だけを指定します。`delimiter` を使用する場合、各 `request` には `request = "AT\r\n"` のように末尾の区切り文字を含める必要があります。`packSize` を使用する場合、デコード後の各リクエストは指定したバイト数と完全に一致する必要があります。

## 応答遅延の書き方

`responseDelay`（グローバル）と `rules[].delay`（ルール単位の上書き）は、どちらも次の 2 通りの書き方を受け付けます。

| 書き方 | 動作 |
| --- | --- |
| `delay = 300` または `delay = "300"` | 300 ms 固定で応答します。 |
| `delay = "100~300"` または `delay = "100-300"` | 応答ごとに 100～300 ms の**一様ランダム**。実機の処理時間のばらつきを再現します。 |

- 単位はミリ秒で、範囲は `0`～`600000` です。区間の区切り文字は `~` と `-` のどちらも使え、前後の空白は省略できます。
- 優先順位：ルール単位の `delay` > グローバルの `responseDelay` > 既定値 `0`。遅延を書かないルールはグローバル値を使用します。
- ランダム範囲の価値は「それらしく見える」ことではなく**境界の検証**にあります。範囲を上位ソフトのタイムアウトしきい値より少し大きくすると、正しく再送するか、同じ応答を二重処理しないかを確認できます。固定値ではこの境界に到達できません。
- 遅延付きの応答が複数ある場合、リクエストの到着順に **FIFO で直列**に送信されます。実機が 1 度に 1 リクエストしか処理しない動作と同じです。
- 誤った値も黙って無視されません。`responseDelay` が不正なら `0` として扱い警告を出し、ルール単位の `delay` が不正ならグローバル値に戻して警告を出します。いずれも読み込み時の問題一覧に表示されます。

## シリアルブリッジのフィールド

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `gateway` | いいえ | 推奨されるルートオブジェクト。内部のフィールドをファイル直下に置くこともできます。 |
| `gateway.endpoints` | はい | 2 つ以上のシリアル端点。同じ物理ポートを重複して指定できません。 |
| `gateway.endpoints[].id` | はい | ルートから参照する一意の端点 ID。 |
| `gateway.endpoints[].name` | いいえ | ログに表示する端点名。既定値は `id` です。 |
| `gateway.routes` | はい | 空ではないルート一覧。1 件以上を有効にする必要があります。 |
| `gateway.routes[].name` | いいえ | 表示名。既定では `route1` などの名前を生成します。 |
| `gateway.routes[].sources` | はい | ルートを開始できる端点 ID の空ではないリスト。 |
| `gateway.routes[].targets` | はい | データの転送先となる端点 ID の空ではないリスト。 |
| `gateway.routes[].enabled` | いいえ | ルートを有効にする設定。既定値は `true` です。 |
| `gateway.highlight` | いいえ | ブリッジログのキーワード強調設定。 |

1 つの端点を複数のルートで使用でき、1 つの送信元から複数の転送先を指定できます。`sources` と `targets` は、すべて `endpoints` で宣言された ID を参照する必要があります。読み込みに失敗した場合は、古いルートを誤って実行しないよう以前のブリッジ設定を消去します。

## テストシーケンスのフィールド

| フィールド | 必須 | 既定値または指定可能な値 | 説明 |
| --- | --- | --- | --- |
| `test` | いいえ | 推奨されるルートオブジェクト | 内部のフィールドをファイル直下に置くこともできます。 |
| `test.connection` | 実行時に必須 | 既定値なし | 接続設定。フィールドは「端点の通信設定」と同じです。 |
| `test.connection.port` | はい | 既定値なし | シリアルポート名またはネットワークエンドポイントアドレス。 |
| `test.connection.baudRate` | いいえ | 既定値 `115200` | ボーレート。 |
| `test.defaults.timeout` | いいえ | 既定値 `1000`、範囲 `1`～`600000` | ステップに `timeout` がない場合の待機上限（ミリ秒）。 |
| `test.defaults.interval` | いいえ | 既定値 `100`、範囲 `0`～`10000` | ステップに `delay` がない場合の送信前待機（ミリ秒）。 |
| `test.steps` | はい | `1`～`500` ステップ | 順番に実行するステップ一覧。 |
| `test.steps[].name` | いいえ | 既定値 `Step N` | レポートに表示するステップ名。 |
| `test.steps[].send` | いいえ | 既定値なし | 送信内容。空の場合は待機のみ行います。 |
| `test.steps[].expect` | いいえ | 既定値なし | 期待値。空の場合は送信のみで判定しません（`match = "silence"` を除く）。 |
| `test.steps[].match` | いいえ | 既定値 `contains` | `contains`、`exact`、`regex`、`silence`。 |
| `test.steps[].timeout` | いいえ | `defaults.timeout` を継承 | このステップの待機上限。 |
| `test.steps[].delay` | いいえ | `defaults.interval` を継承 | このステップの送信前待機。 |
| `test.steps[].encoding` | いいえ | 既定値 `ascii` | `ascii` または `hex`。`send` の解釈と `expect` の比較方法の両方を決めます。 |

判定の仕様：

- `contains` は部分文字列、`exact` は前後の空白を除いて完全一致、`regex` は正規表現の部分一致、`silence` はタイムアウト時間内に**1 バイトも受信しない**ことを要求します。
- 照合はタイムアウト時間内でポーリングします。受信内容が一致した時点で即座に成功となり、`timeout` の満了を待ちません。失敗と判定されるのはタイムアウトした場合だけです。
- `encoding = "hex"` の場合、`send` は `"41 54 0D 0A"` のようなバイト列として解釈され、`expect` も空白を除いて大文字化した HEX 文字列として比較されます。`ascii` の場合は UTF-8 テキストとして比較し、前後の空白は無視します。
- 設定の誤りは実行途中ではなく読み込み時に検出します。`send` も `expect`/`silence` もないステップ、不正な正規表現、不正な HEX、空のステップ一覧、500 ステップ超はすべて読み込みを拒否します。

## 端点の通信設定

デバイス模擬の `endpoint` とシリアルブリッジの `endpoints[]` は、次の通信フィールドを共有します。

| フィールド | 必須 | 既定値または指定可能な値 | 説明 |
| --- | --- | --- | --- |
| `port` | はい | 既定値なし | シリアルポート名（`COM3`、`/dev/ttyUSB0`）またはネットワークエンドポイントアドレス。下記「ネットワークエンドポイントの書き方」を参照。 |
| `baudRate` | シリアルのみ | 0 より大きい整数 | `9600`、`115200` などのボーレート。ネットワークエンドポイントでは省略可能。 |
| `dataBits` | いいえ | 既定値 `8`、範囲 `5`～`8` | データビット数。 |
| `stopBits` | いいえ | 既定値 `1`、選択肢 `1`、`1.5`、`2` | ストップビット数。 |
| `parity` | いいえ | 既定値 `none` | `none`、`odd`、`even`、`mark`、`space`。 |
| `flowControl` | いいえ | 既定値 `none` | `none`、`rts_cts`、`dsr_dtr`、`xon_xoff`。`/` を含む形式も使用できます。 |

`autoOpen` は記述しないでください。設定の読み込みは検証と準備だけを行い、「実行」をクリックした後にシリアルポートを開きます。

## ネットワークエンドポイントの書き方

`port` フィールドはシリアルポート名のほかに、次のネットワークアドレスを受け付けます（大文字小文字は区別しません）。

| 書き方 | 動作 |
| --- | --- |
| `tcp://192.168.1.20:8080` | TCP クライアント：リモートのシリアルサーバー（ser2net、ESP-Link、USR-TCP232 など）に接続 |
| `tcp://:9000` / `tcp-listen://9000` | TCP サーバー：ローカルで待ち受け、対向の接続を待つ（同時に 1 クライアント。後からの方が優先） |
| `udp://192.168.1.20:9000` | UDP：固定の対向先とデータグラムを送受信（シリアル⇔UDP 変換モジュールで一般的） |
| `udp-listen://9000` | UDP ポートで待ち受け、最初に受信したデータグラムの送信元アドレスに返信 |

ネットワークエンドポイントと物理シリアルポートは同じ設定ファイル内で自由に混在でき、ルートは従来どおりエンドポイント ID で参照します。注意点：

- ネットワークエンドポイントにはボーレートの概念がないため、`baudRate`、`parity` などのシリアルパラメータはすべて省略できます。物理シリアルポート側のパラメータは、そのエンドポイント自身のフィールドで設定します。
- DTR / RTS / BREAK のライン制御はローカルの電気信号であり、ネットワーク越しには**伝わりません**。データの送受信には影響しません。
- 待ち受けポートは同時に 1 クライアントのみ受け付けます。`udp-listen` の返信先は、最初に受信したデータグラムの送信元アドレスです。

双方向透過の完全な例は [10-network-endpoints.conf](10-network-endpoints.conf) を参照してください。

## ログ強調フィールド

デバイス模擬では `simulator.highlight`、シリアルブリッジでは `gateway.highlight` を使用します。内部のフィールドは共通です。

| フィールド | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `highlight.enabled` | いいえ | キーワード指定時は `true` | キーワード強調を有効にします。 |
| `highlight.ignoreCase` | いいえ | `true` | 照合時に大文字・小文字を区別しません。 |
| `highlight.keywords` | いいえ | 空のリスト | 強調表示するテキストキーワードの一覧。 |
